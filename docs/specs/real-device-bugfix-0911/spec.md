# 规格：real-device-bugfix-0911 八项真机问题修复

> 事实源：`docs/specs/real-device-bugfix-0911/BRIEF.md`（逐项根因代码级实证 + 用户真机日志实锤，均已验证）。
> 交付形态：一次 openspec 立项，分批次 A/B 两波实施，最终打一个测试包交用户真机验收。

## Intent

本规格覆盖 2026-09-11 用户真机反馈的八项问题（F1~F8）及检查点 1 修订新增的 F9（日志治理）/F10（TTS 联调测试保障）：视频下载文件无后缀导致软件内不可播（P0）、书源/订阅源管理列表底部全选条与长按菜单重叠（P1）、内置对话高亮长对话失配与编辑生效性存疑（P0）、内置高亮规则扩充（P2）、网络稳定性系统性优化（HostAccessStrategy，P0）、缓存清理入口整合（P2）、TXT 目录与替换净化内置规则扩充（P2）、TTS 多角色可用性断链（P0）、日志降噪与规范优化（P1）、TTS 功能级联调测试保障（P1）。全部根因经代码级实证（文件:行号）与用户真机日志双重验证，修复坚持正向优化——功能更好用、更稳定，不规避日志、不静默吞错误；八项全量一批处理，最终以一个测试包由用户真机验收。

## Scope

### In-Scope

- **F1（P0）视频下载后缀与可播放性**：文件名解析非空标题分支补视频扩展名；DIRECT 直链下载完成按响应 Content-Type 纠正；下载管理对无扩展名旧文件兜底可播；标题含 `.` 伪后缀防护；MPEG4Writer 崩溃应用侧规避（封装异常保护+阅读状态保存）并登记
- **F2（P1）管理列表底部全选条**：去掉书源/订阅源管理 Compose 常驻底部全选/反选条；多选态批量操作收口单一入口；13 项批量操作与选择计数不丢；真机复核旧 View 选择条双栈重叠来源
- **F3（P0）高亮规则修复**：内置对话正则放宽（限长上限 120→400、保留 `\n` 排除即首版不跨段，防 ReDoS）；字面量模式填正则内容给提示；匹配器补 isRegex/命中统计诊断日志；评估"长度上限"规则级配置
- **F4（P2）内置高亮规则扩充**：候选 16 条选优内置；新增高亮版本旗标打通"新增规则推给老用户"（MERGE 追加缺失 id，不动用户修改）；默认开关策略=确定性/修复性开、泛化易误伤关
- **F5（P0）网络稳定性系统性方案（HostAccessStrategy v1.1，两阶段收编口径）**：阶段1（本批交付）=以 host 为键的健康表（ConcurrentHashMap 上限 400+fail-open 兜底）承载 DNS 层选路+坏 IP 有记忆（键=host+IP 对短 TTL 黑名单+指数退避 30s→5min→15min）+Cronet/OkHttp 错误分类处失败上报+后台 DNS 探测单调度器收编；阶段2（登记后续）=Cronet per-host 状态字段迁移（仅状态字段不改拦截流程结构，全局降级不误伤健康 host）；per-host 自适应与 failUrl TTL 语义并入健康表；TTS 音频下载静默替代补可见提示；"图片绘制缓存"说明文案澄清作用域
- **F6（P2）缓存清理整合**：删除其它设置"清除缓存/清除 WebView 数据"两入口；WebView 数据迁为缓存管理第 4 分项（保留"删除后需重启"提示语义）；废弃函数清理
- **F7（P2）TXT 目录/替换净化内置规则**：替换净化 0→12 条（全源空白自建，新建导入链，内置负 id 约定）；TXT 目录 26→30（MD3 独有 2 条直接采纳+社区候选选优 2 条，版本旗标增量追加）；字典不扩（调研确认本仓 5 条已最高档）
- **F8（P0）TTS 多角色可用性**：开关正名"AI 分镜选角"并区分语义；系统引擎音色枚举（getVoices）打通 CloneTTS 系统音色绑定→真实多声；模板激活未绑音色面板可见提示；对话切分统计可见；脚本/HTTP 声源限制明示；模板管理 CloneTTS 引导
- **F9（P1）日志治理**：AppLog 新增 putThrottled/putSampled 双机制；周期性日志禁令；噪音源逐项治理（MemoryPressure/LiveEventBus/CryptoScope/预连接/MIUI SettingTrigger）；正式诊断日志（TtsTrace/PageDebug）白名单保留只降频
- **F10（P1）TTS 功能级联调测试**：ai_tests 新增 TTS L2 联调脚本（引擎枚举/音色枚举/模板绑定/朗读推进 TtsTrace 断言）；模拟器环境准备（CloneTTS APK 官方 GitHub Releases；MultiTTS 无官方渠道仅真机用户提供）；覆盖度矩阵落 design 3.9

### Out-of-Scope（对齐 BRIEF"明确不做"）

- Cronet 拦截流程结构不重写：HostAccessStrategy 分两阶段收编——阶段1（本批）=DNS 层接入+失败上报+坏 IP 黑名单；阶段2（登记后续）=Cronet per-host 状态字段迁移（收编仅状态字段不改拦截流程结构，入口全局门移除与 in-band 探测重构独立立项）
- 脚本/HTTP 声源进逐段 multiRole 合成链（架构级，登记后续）
- DoH 上游服务器可配置化（保持内置两家）
- 字典规则扩充（现 5 条即上游通用集）
- MPEG4Writer 平台库缺陷根治（应用侧规避+登记）
- AI 角色绑定链 characterId 透传（依赖段落坐标系验证，登记后续）

## Approach

### Selected Approach

两波实施、一个测试包验收（用户裁决八项全量一批处理）：

- **批次A（P0 bug+稳定性）**：F1（含 MPEG4Writer 排查规避）、F3、F5（HostAccessStrategy v1.1）、F8、F9（日志治理）→ 编译+单测
- **批次B（体验+扩充）**：F2、F4、F6、F7、F10（TTS 联调测试脚本先行）→ 编译+单测
- **验收**：最终打一个测试包交用户真机自测，提供 TtsTrace/网络日志复核 HostAccessStrategy 成功率对比与多角色 dialogue 命中率

关键机制走向（行为生效路径，细节归 design/tasks）：

- 三类内置规则（高亮/替换净化/TXT 目录）统一走"版本旗标→增量 MERGE 追加缺失 id→不动用户已有修改"的推送模型：高亮新增高亮版本旗标；Room 类走 DefaultData.upVersion + LocalConfig 版本旗标；替换净化新建导入链并遵循内置负 id 约定
- TTS 多角色核心为系统引擎音色枚举（TextToSpeech.getVoices）：枚举真实音色→模板编辑器直选→写 toneID→朗读时命中 setVoice，打通"多角色真的多声音"
- 网络层升级为 HostAccessStrategy 单源化方案（两阶段收编）：阶段1=host 健康表 DNS 层接入+Cronet/OkHttp 错误分类处失败上报+坏 IP 短 TTL 黑名单+指数退避+单调度器 DNS 探测+fail-open 兜底；阶段2（登记后续）=Cronet per-host 状态字段迁移（收编仅状态字段不改拦截流程结构）；Cronet 拦截流程结构本批与阶段2 均不重写
- 日志治理以 AppLog putThrottled/putSampled 双机制收编各处自建频控，周期性日志禁令+级别语义纪律；诊断 tag 白名单豁免（只降频不删除）
- TTS 测试保障以模拟器 L2 联调脚本覆盖约 80% 功能面（引擎枚举→音色枚举→绑定→朗读推进），L3 真机仅用户（听感/后台保活/功耗）

### Alternatives Considered

| 方案 | 否决理由 |
|------|---------|
| 仅修 P0（F1/F3/F5/F8），不做扩充与整合类项 | 用户已裁决八项全量一批处理；F2/F4/F6/F7 同为真机反馈来源，不修则问题原样保留、下轮重复立项 |
| 内置规则库照抄上游 gedoor/legado | 上游替换净化内置同样为 0 条；上游高亮机制与本项目不同（内置 id/愈合/版本旗标机制不兼容），照抄解决不了"新增规则推不到老用户"的核心缺口 |
| 重写 Cronet 降级-恢复机制 | 收编而非重写：HostAccessStrategy 仅统一记账与选路，保留既有降级-探测-切回自愈语义，风险可控（用户裁决口径） |
| DoH 上游服务器可配置化 | 超出本期边界；保持内置两家，稳定性优化聚焦回退策略而非配置面扩展 |
| 静默降级维持现状（TTS/网络失败不提示） | 违背用户"正向优化、不静默吞错误"总要求；静默正是本次断链根因之一，必须转为可见提示 |

### Drawbacks

- **平台缺陷无法根治**：MPEG4Writer UBSan 溢出崩溃属 Android16/MIUI 平台库缺陷，应用侧仅能做封装异常保护+阅读状态保存，根治登记不承诺
- **正则放宽的性能风险**：对话长度上限放宽（首版不跨段）在长章多命中场景可能放大耗时 → 兜底：保留限长与既有 3000ms 超时保护，单测覆盖确定性与 ReDoS 预算
- **新增内置规则误伤风险**：泛化匹配可能误伤正文 → 兜底：泛化类默认关；TXT 目录增量默认开基于 vreader 案例（默认开收益大于误伤风险）
- **HostAccessStrategy 行为调整的解析波动**：健康表选路+坏 IP 黑名单可能改变部分主机访问路径 → 兜底：永远兜底系统 DNS、坏 IP 短 TTL（2min）+探测自愈防误杀、交付时用日志复核成功率对比
- **日志治理合并可能吞掉个别明细**：putThrottled/putSampled 在极端高频场景可能合并个别明细 → 兜底：诊断 tag 白名单豁免（TtsTrace 等不受节流采样影响），级别语义纪律保证关键失败仍可见
- **音色枚举依赖厂商引擎质量**：getVoices 返回质量参差或为空时多角色体验受限 → 兜底：枚举为空时维持现状并明示引导，不阻塞基础朗读
- **删除其它设置清理入口属习惯路径变更**：老用户找不到原入口 → 兜底：能力完整迁移缓存管理并保留"需重启"提示语义
- **待复测项不实锤不修**：视频嗅探解析失败×2、BufferSpeed SLOW×245 仅登记观察，本期不处理

## Requirements

### Requirement: R1 视频下载文件必须可播放（F1）

系统 SHALL 保证用户下载的视频落盘文件带正确视频扩展名且软件内可直接播放；对历史遗留的无扩展名文件提供兜底播放能力；文件名判定不因标题中的点号误判扩展名；转封装异常时用户阅读状态不丢失。

**验收口径**：真机下载视频带后缀可播；单测覆盖文件名后缀逻辑（含伪后缀防护）。

#### Scenario: 下载无后缀文件可播
- **WHEN** 用户在书源/订阅源内下载一个视频，且下载标题不含扩展名
- **THEN** 下载完成后落盘文件自动带上正确视频扩展名，在下载管理点击即可软件内播放，无需手动改后缀

#### Scenario: 直链下载按响应类型纠正
- **WHEN** 直链下载的响应头标注为视频类型，但文件名解析结果缺少视频扩展名
- **THEN** 下载完成后按响应类型纠正落盘文件扩展名，文件与实际格式一致且播放正常

#### Scenario: 无扩展名旧文件可播
- **WHEN** 用户打开此前版本下载的、无扩展名的视频文件
- **THEN** 下载管理将其按视频处理并可正常播放（默认按视频处理或文件头嗅探），不要求用户手动改后缀

#### Scenario: 标题伪后缀防护
- **WHEN** 视频标题含"xx.4K"之类带点字样
- **THEN** 落盘文件名仍正确补上视频扩展名，不把点号后内容误当扩展名导致错误后缀或双后缀

#### Scenario: 转封装异常不丢阅读状态
- **WHEN** 下载转封装过程中发生平台级封装异常
- **THEN** 应用侧捕获保护并保证用户当前阅读状态已保存，该平台缺陷登记在案

### Requirement: R2 管理列表批量操作单一入口（F2）

系统 SHALL 移除书源管理/订阅源管理列表底部常驻"全选/反选"操作条，消除与长按弹出的全选反选重叠；进入多选态后通过单一入口可执行全选/反选及全部既有批量操作（启用/停用/加组/置顶/校验/导出/删除等 13 项），选择计数显示保留。

**验收口径**：真机底部条消失且批量操作可达；确认无新旧两套全选控件同时显示；多选态下新旧两套全选/反选控件不同时显示。

#### Scenario: 底部条去掉后批量操作可达
- **WHEN** 用户长按列表项进入多选态
- **THEN** 列表底部不再出现常驻全选/反选条，且通过多选态单一入口（顶栏溢出菜单或选择态菜单）可完成全选、反选与启用/停用/加组/置顶/校验/导出/删除等全部批量操作

#### Scenario: 非多选态不受干扰
- **WHEN** 用户未进入多选态、正常浏览书源/订阅源列表
- **THEN** 页面不出现任何底部全选操作条，浏览体验与普通列表一致

#### Scenario: 选择计数显示保留
- **WHEN** 用户在多选态选中若干列表项
- **THEN** 选择计数（已选/总数）正确显示，作为批量操作的状态依据

#### Scenario: 双栈重叠消除
- **WHEN** 用户在真机分别打开书源管理与订阅源管理页
- **THEN** 不存在两个全选控件同时渲染的重叠显示

### Requirement: R3 内置对话高亮长对话命中与编辑生效（F3）

系统 SHALL 使内置对话高亮命中单段长对话（单段长度上限放宽至 400 字符、保留限长防 ReDoS；首版不跨段）；用户编辑规则保存后立即生效于当前阅读页；当用户填写正则内容但未开启正则开关时给予明确提示；非法正则不再完全静默（诊断日志+提示）；用户对内置规则的手工修改在愈合时不被覆盖。

**验收口径**：真机长对话高亮命中、编辑正则即时生效；单测覆盖放宽后正则的确定性与性能（ReDoS 预算）；高亮链路诊断日志保留。

#### Scenario: 长对话高亮命中
- **WHEN** 用户打开一章含单段长对话（超出原 120 字上限、不超过 400 字符）的内容
- **THEN** 对话文本被内置规则命中并高亮，不再整段漏匹配；边界说明：超长（>400）与跨段对话命中登记后续（首版不跨段）

#### Scenario: 编辑正则即时生效且有提示
- **WHEN** 用户编辑某条高亮规则的正则并保存
- **THEN** 当前阅读页立即重绘生效，无需重启或重进；若规则处于字面量匹配模式而内容含正则元字符，系统给出明确提示说明当前不会按正则解析

#### Scenario: 非法正则可感知
- **WHEN** 某条规则的正则在运行期非法
- **THEN** 该规则被跳过但产生诊断日志（含 isRegex/命中统计），可定位问题而非完全无感

#### Scenario: 内置愈合保留用户修改
- **WHEN** 用户曾修改过某条内置高亮规则且内置规则库发生刷新
- **THEN** 用户的修改被保留，不被内置默认值覆盖

### Requirement: R4 内置高亮规则扩充并推给老用户（F4）

系统 SHALL 将内置高亮规则从 12 条扩充至 24 条（新增 12 条：候选 16 条选优+跨段变体，跨段变体默认关），并通过新增版本旗标把新增规则增量推送给老用户（追加缺失规则、保留用户修改）；默认开关遵循"确定性/修复性默认开、泛化易误伤默认关"。

**验收口径**：真机老用户升级后新增内置规则出现且用户修改保留（推送采用"只追加缺失 id、不重置用户已有修改/开关状态"）；跨段变体默认关且真机长章多命中场景性能验证（耗时受控）；默认开关对齐策略；单测覆盖版本旗标触发逻辑。

#### Scenario: 新内置规则推给老用户（高亮版本旗标）
- **WHEN** 已有 12 条内置规则记录的老用户升级到新版
- **THEN** 版本旗标触发增量追加，第 13 条及以后的新内置规则出现在规则列表，用户对既有规则的修改不被覆盖

#### Scenario: 默认开关策略
- **WHEN** 新一批内置规则进入默认配置
- **THEN** 确定性/修复性规则默认开启，泛化易误伤规则默认关闭；跨段变体默认关闭

#### Scenario: 跨段变体真机性能验证
- **WHEN** 用户在长章多命中场景开启跨段变体规则
- **THEN** 高亮耗时受控（既有 3000ms 超时保护内），性能可接受后方可默认策略定稿

#### Scenario: 新规则可自主管理
- **WHEN** 用户不想要某条新增内置规则
- **THEN** 可按现有规则管理方式单独关闭或编辑，行为与既有内置规则一致

### Requirement: R5 系统性网络可用性（F5，HostAccessStrategy v1.1）

系统 SHALL 建立以 host 为键的单源化访问健康表（HostAccessStrategy）：按 {调用栈, 解析通道} 维度记录判定（stackVerdict/dnsVerdict）并据此前置选路；对坏 IP 具备记忆（键=host+IP 对的短 TTL IP 黑名单+指数退避 30s→5min→15min）；关键状态迁移打点；健康表自身故障 SHALL fail-open（pickChannel/report/probe 全路径异常回落默认通道，不阻断网络访问）。本需求分两阶段交付：阶段1（本批）=DNS 层接入（DohDns 退避期直走系统 DNS）+Cronet/OkHttp 错误分类处失败上报+坏 IP 黑名单+后台 DNS 探测单调度器收编（HEAD 探测仅清 dnsVerdict，stackVerdict 恢复沿用既有 Cronet in-band 探测）；阶段2（登记后续）=Cronet per-host 状态字段迁移（全局降级不再误伤健康 host；收编仅状态字段不改拦截流程结构）。原 DoH 回环/保留地址判败、per-host 自适应回退、failUrl TTL 语义并入该策略；Cronet 拦截流程结构不重写。附属交付：TTS 音频下载失败的静默替代附用户可见提示；"图片绘制缓存"设置增加作用域说明；内存压力日志降频移交 R9 日志治理。

**验收口径**：真机弱网/切换网络场景访问成功率体感提升，导出日志复核坏 IP 重复消耗与 DoH fallback 统计下降；单测覆盖健康表记账/指数退避/TTL 过期判定纯函数；fail-open 行为验证（健康表异常时网络访问不受阻）；阶段1 本批交付=坏 IP 有记忆+DNS 选路+fail-open，阶段2（Cronet per-host 迁移）登记后续；L1 装机零 FATAL；网络诊断日志保留。

#### Scenario: 坏 IP 有记忆不再超时循环
- **WHEN** 某主机 DoH 解析返回的 IP 连接失败（连接拒绝/超时）
- **THEN** 该 IP 进入短 TTL（2min）黑名单并上报 BAD_IP 嫌疑，退避期内该主机直接走系统 DNS，不再重复等待完整连接超时（消除 60s 超时循环浪费）

#### Scenario: 健康 host 不被全局降级误伤（阶段2 登记后续）
- **WHEN** 全局进入降级会话状态（原 certErrorCache/degradedForSession 场景）
- **THEN** 健康表标记健康的 host 仍按原优选通道访问，不随全局降级切换（消除降级-恢复震荡根因）；该场景依赖 Cronet per-host 迁移，属阶段2 登记后续，本批不交付

#### Scenario: 退避期直走系统 DNS
- **WHEN** 某主机的解析通道连续失败达到退避条件
- **THEN** 退避期内该主机解析直接走系统 DNS，退避间隔按 30s→5min→15min 指数递增，不再重复消耗 DoH 查询

#### Scenario: 单调度器探测恢复（DNS 层）
- **WHEN** 存在处于退避期的主机
- **THEN** 由单一后台调度器执行 HEAD 轻探测：探测仅清 dnsVerdict（DNS 层验证），成功清记录恢复优选、失败退避翻倍；stackVerdict 恢复沿用既有 Cronet in-band 真实请求探测（防探测栈错位，HEAD 走 OkHttp 无法证明 Cronet 可用）；Cronet half-open 探测归一属阶段2

#### Scenario: 健康表故障不熔断网络（fail-open）
- **WHEN** 健康表查询/上报/探测任一环节发生内部异常
- **THEN** 该环节立即回落默认通道（Cronet 开关原语义+系统 DNS），网络访问不受健康表故障阻断

#### Scenario: failUrl TTL 后可重试
- **WHEN** 某资源 URL 因瞬时网络失败进入失败黑名单
- **THEN** TTL 过期后同一 URL 重新可发起请求并有机会成功（连续失败按 5min→10min→20min 退避封顶），而非持续秒失败直至缓存淘汰

#### Scenario: TTS 音频下载失败可见提示
- **WHEN** TTS 音频下载失败触发静默无声音频替代
- **THEN** 用户收到一条可见提示说明该段音频失败，不再完全无感

#### Scenario: 图片绘制缓存作用域澄清
- **WHEN** 用户查看"图片绘制缓存"设置项
- **THEN** 说明文案澄清其只作用于正文位图缓存、不影响封面加载，不再误导排障方向

#### Scenario: Cronet 机制行为不回归
- **WHEN** 使用中遇到 Cronet 降级或恢复场景
- **THEN** 既有自愈语义经收编后保持不变，健康表统一记账不改变降级-恢复行为契约，仅新增健康 host 保护与状态迁移打点

### Requirement: R6 缓存清理入口整合（F6）

系统 SHALL 移除其它设置中的"清除缓存/清除 WebView 数据"入口，将缓存清理能力统一收口到缓存管理页；WebView 数据成为缓存管理第 4 分项并保留"删除后需重启"提示语义；既有播放中保护与 exoplayer 外部缓存分项能力不回退。

**验收口径**：真机其它设置无重复入口、缓存管理可完成 WebView 数据清理；功能不缺失。

#### Scenario: 其它设置入口删除后缓存管理可用 WebView 清理
- **WHEN** 用户进入其它设置页
- **THEN** 不再出现"清除缓存/清除 WebView 数据"两个入口；进入缓存管理页可见并可选择清理 WebView 数据，且看到"删除后需重启"提示

#### Scenario: 清理能力不回退
- **WHEN** 用户在缓存管理执行清理
- **THEN** 原有三分项与 exoplayer 外部缓存仍可管理，播放进行中的保护行为保持不变

### Requirement: R7 替换净化与 TXT 目录内置规则扩充（F7）

系统 SHALL 新增替换净化内置规则集 12 条（0→12，全源空白场景下自建；经内置导入链下发，遵循内置负 id 约定，不干扰用户自建规则），并按版本旗标向老用户增量追加 TXT 目录规则（26→30：MD3 独有 2 条直接采纳+社区候选选优 2 条）；字典规则不扩充（调研确认本仓 5 条已最高档）；默认开关遵循"错字修正/HTML 清理类默认开、泛化关键词整行删默认关、TXT 目录增量默认开（中文顶格标题默认关）"。

**验收口径**：真机替换净化内置规则出现、TXT 目录新规则推给老用户且老规则不被改动（推送采用"只追加缺失 id、不重置用户已有修改/开关状态"）；单测覆盖版本升级推送逻辑。

#### Scenario: 替换净化内置规则出现
- **WHEN** 用户升级到新版并打开替换净化规则列表
- **THEN** 出现内置规则（如章末推广块清理、HTML 残留清理、script 块清理等），其中错字修正/HTML 清理类默认开启、泛化整行删类默认关闭

#### Scenario: 内置追加不影响用户自建规则
- **WHEN** 用户此前已自建替换净化规则
- **THEN** 内置规则以独立条目追加，用户自建规则的内容与开关不受影响

#### Scenario: TXT 目录增量推送
- **WHEN** 老用户升级到新版
- **THEN** 版本旗标升级后新增 TXT 目录规则被追加，用户已有目录规则与修改不被改动

### Requirement: R8 TTS 多角色真实可用（F8）

系统 SHALL 打通"模板激活→绑定真实音色→多角色多声"闭环：朗读设置开关正名为"AI 分镜选角"并区分语义；系统引擎枚举真实音色供模板绑定（含 CloneTTS 注册的系统音色），绑定后朗读真实区分角色；模板激活但音色未绑定时面板给出可见提示与引导；面板显示旁白/对话切分统计；脚本/HTTP 声源逐段路径限制明示；模板管理页提供 CloneTTS 使用路径引导。

**验收口径**：真机多角色绑定 CloneTTS 系统音色后对话与旁白真实双声；TtsTrace 诊断日志保留；单测覆盖音色枚举映射纯函数部分。

#### Scenario: TTS 绑定 CloneTTS 系统音色后多角色真实双声
- **WHEN** 用户在模板编辑器中为对话/旁白分别选择 CloneTTS 注册的系统音色并开始多角色朗读
- **THEN** 对话段与旁白段使用各自绑定的不同真实音色播报，不再全部为引擎默认单声

#### Scenario: 模板激活但未绑音色时面板可见提示
- **WHEN** 选角模板已激活但未绑定具体音色，或朗读结果全部为旁白
- **THEN** 面板显示提示条明示当前状态并引导"去绑定音色"，不再静默降级单声

#### Scenario: 入口语义澄清
- **WHEN** 用户查看朗读设置中的"AI 分镜选角"开关
- **THEN** 开关名称与描述明确其仅作用于 AI 分镜选角，与选角模板路由区分，不再误以为开启即自动多声音

#### Scenario: 切分统计可见
- **WHEN** 用户使用多角色朗读并查看面板
- **THEN** 面板显示旁白/对话切分计数统计，可据此判断切分命中率

#### Scenario: 脚本声源限制明示
- **WHEN** 用户将脚本（HTTP 通道）声源用于逐段多角色合成
- **THEN** 系统给出门禁提示与文案说明该通道的逐段限制，而非静默降级默认音

#### Scenario: 模板管理首次引导
- **WHEN** 用户首次进入模板管理页
- **THEN** 看到 CloneTTS 使用路径说明（系统引擎音色直选），配置路径可循

#### Scenario: 音色枚举三态处理
- **WHEN** 用户在模板编辑器打开系统引擎音色枚举
- **THEN** 三态处理且禁止静默回落：引擎未就绪→提示重试；引擎就绪但空集→明示"该引擎无可枚举音色"；正常→枚举音色；基础朗读功能不受影响

### Requirement: R9 日志治理（F9，检查点 1 新增）

系统 SHALL 在 AppLog 提供周期日志治理双机制：putThrottled（同 key 时间窗去重+末条合并累计次数）与 putSampled（每 n 条汇总 1 条）；确立周期性日志禁令与 E/W/I/D 分级语义纪律；对既有噪音源逐项治理（MemoryPressure 5521 条/会话→<10、LiveEventBus 3039、CryptoScope 1211、预连接 740、MIUI SettingTrigger）；正式诊断日志（TtsTrace/PageDebug 等）白名单保留、只降频不删除。

**验收口径**：同场景导出日志，噪音占比显著下降且诊断链完整（TtsTrace 等关键链路日志不缺失）；单测覆盖节流/采样机制；logging_rules.md 三条款增补（周期日志禁令/级别语义表/双机制使用指南）。

#### Scenario: 导出日志噪音占比显著下降
- **WHEN** 用户在与治理前相同的使用场景导出日志
- **THEN** 周期性噪音日志（内存压力/事件总线/加解密作用域/预连接）数量较治理前显著下降（MemoryPressure <10 条/会话量级），噪音占比明显降低

#### Scenario: 诊断链完整不受治理影响
- **WHEN** 治理后的日志被用于真机异常分析
- **THEN** TtsTrace 等白名单诊断日志链完整可循（只降频不删除），关键失败与状态迁移仍可观测

#### Scenario: 双机制收编自建频控
- **WHEN** 新增或改造需要频控的日志点
- **THEN** 统一使用 putThrottled/putSampled，不再各处自建频控逻辑；级别按 E/W/I/D 语义对号入座

### Requirement: R10 TTS 功能级联调测试保障（F10，检查点 1 新增）

系统 SHALL 在 ai_tests 新增 TTS 功能级 L2 联调脚本，覆盖"引擎枚举→音色枚举→模板绑定→朗读推进"功能链（TtsTrace 断言）；提供模拟器环境准备路径（CloneTTS APK 经官方 GitHub Releases 安装并设默认引擎；MultiTTS 无官方渠道，仅真机用户提供）；覆盖度矩阵落 design 3.9 并登记 ai_tests/docs。

**验收口径**：模拟器完成"引擎枚举→音色枚举→模板绑定→朗读推进"功能链验证且 TtsTrace 断言命中（L2-a 断言前置=枚举路径 TtsTrace 埋点完成后方可执行，埋点随 R8 音色枚举交付）；环境准备含 tts_default_lang/country/variant 三键设置与 CloneTTS 首启手动初始化（模型下载/授权）一次；脚本可重复执行；CloneTTS benchmark 失败时有降级验证路径。

#### Scenario: 模拟器 TTS 功能链联调
- **WHEN** 在已安装 CloneTTS 并设为默认引擎的模拟器上执行 TTS L2 联调脚本
- **THEN** 引擎枚举、音色枚举、模板绑定、朗读推进逐项通过且 TtsTrace 断言命中

#### Scenario: 模拟器性能不足时降级验证
- **WHEN** CloneTTS 内置 benchmark 在模拟器 x86 环境跑失败（NPU 依赖/RTF>1）
- **THEN** 降级为系统 TTS 接口模式验证功能链，功能面覆盖不受阻并记录降级结论

#### Scenario: 覆盖度矩阵登记
- **WHEN** TTS 联调测试方案定稿
- **THEN** 覆盖度矩阵（单测/模拟器 L2/真机 L3 各覆盖项，模拟器约 80% 功能面）落 design 3.9 并在 ai_tests/docs 登记

## 交叉确认

- R1~R8 与事实源 F1~F8 一一对应；R9/R10 对应检查点 1 修订新增的 F9/F10（依据 BRIEF v1.1 补充调研结论），无遗漏
- Out-of-Scope 与 BRIEF"明确不做"对齐（Cronet 条口径为两阶段收编：阶段1 DNS 层本批交付，阶段2 per-host 状态字段迁移登记后续，拦截流程结构不重写）
- 批次划分与验收形态对齐 BRIEF"批次划分"与"验证口径"两节（批次A 含 F9、批次B 含 F10）
- 诊断日志保留铁律遵守：高亮链路/TtsTrace/网络诊断日志只增不清（F9 治理仅降频+白名单豁免）
